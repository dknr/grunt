# grunt

A simple chat protocol for Grugs.

## Features

- **Real-time Chat** — Server-Sent Events (SSE) pub/sub messaging with automatic join/leave notifications
- **Web UI** — Modern dark theme interface with hash-based avatars, grouped messages, and mobile support
- **HTMX Architecture** — Server-side rendering with HTML fragments for fast, lightweight interactions
- **User Management** — Registration via invite codes (10-minute expiry), login, password changes
- **Admin System** — Manage users, generate API keys, control access
- **API Keys** — `gk_` prefixed keys for programmatic access with SHA-256 hash storage
- **Message History** — Sync endpoint for retrieving past messages with pagination
- **SQLite Backend** — Pure Go implementation (in-memory or on-disk)

## Quick Start

### 1. Start the Server

```bash
grunt serve                           # In-memory database (default)
grunt serve /path/to/grunt.db         # On-disk persistent storage
```

The server starts on `http://localhost:54765` by default.

### 2. Register Your First User

Open the web UI at `http://localhost:54765`. The first user to register is automatically granted admin privileges.

Or via CLI (requires an invite code):

```bash
GRUNT_LOGIN=admin:secret grunt send "Hello, Grugs!" --invite-code ABC123DEF456
```

### 3. Generate Invite Codes (Admin)

Log in as admin and visit the settings page to generate invite codes. Codes expire after 10 minutes.

### 4. Send Messages via CLI

```bash
GRUNT_LOGIN=user:pass grunt send "Hello, Grugs!"
```

### 5. Receive Messages via CLI

```bash
GRUNT_LOGIN=user:pass grunt recv --invite-code CODE
```

### 6. Use the REPL

```bash
GRUNT_LOGIN=user:pass grunt repl --invite-code CODE
```

## Web UI

The built-in web interface provides a complete chat experience:

- **Chat View** — Real-time message stream with grouped messages (same user within 1 minute)
- **Avatars** — Hash-based avatars for each user
- **Settings Page** — Password change, logout, admin controls
- **Mobile Support** — Responsive layout with proper keyboard handling on Chrome Android

Access the web UI at `http://localhost:54765`.

## Authentication

### Bearer Token Authentication

All API endpoints (except registration and login) require a Bearer token in the `Authorization` header:

```bash
curl -H "Authorization: Bearer <token>" http://localhost:54765/api/chat/sync?since=0
```

Tokens are obtained via the login endpoint or generated programmatically.

### API Key Authentication

Admin-generated API keys (`gk_` prefix) can be used for programmatic access:

```bash
curl -H "Authorization: Bearer gk_<key>" http://localhost:54765/api/chat/sync?since=0
```

API keys are hashed with SHA-256 and stored securely. The raw key is shown only once at creation.

### Invite Codes

New users must provide a valid invite code to register. Codes:
- Expire after 10 minutes
- Can only be used once
- Are generated by admins via the web UI or API

## Admin Panel

Admins have access to:

- **User Management** — Create users without passwords (for service accounts)
- **API Key Management** — Generate, list, and revoke API keys for users
- **Invite Code Generation** — Create new invite codes with 10-minute expiry

Access the admin panel via the settings page in the web UI.

## Architecture

```
cmd/grunt/        - CLI commands (serve, send, recv, repl)
server/           - SSE hub, HTTP server, API handlers
server/storage/   - SQLite data layer with bcrypt password hashing
client/           - Go client library for programmatic access
deno-client/      - Deno-based send client
```

### Data Flow

1. Client sends message via REST API or web UI
2. Server saves message to SQLite
3. Hub broadcasts message to all connected SSE subscribers
4. HTML clients receive server-rendered fragments via HTMX
5. JSON clients receive raw message data with event type annotations

## API Endpoints

### Authentication

- `POST /api/user/register` — Register a new user (requires invite code)
- `POST /api/user/login` — Login and obtain bearer token

### Messages

- `GET  /api/chat/sync?since=0&last=100` — Retrieve message history
- `POST /api/chat/message` — Send a new message
- `GET  /api/chat/stream` — SSE stream (accept: text/event-stream)

### Admin (requires admin privileges)

- `GET    /api/admin/api-keys` — List all API keys
- `POST   /api/admin/api-keys` — Create API key for a user
- `DELETE /api/admin/api-keys/:id` — Revoke an API key
- `POST   /api/admin/users` — Create a user (no password)

### User Settings

- `POST /api/user/password` — Change password

## Dependencies
